# 收據金額辨識:先獨立推理數零,再填數字,順序排在其他欄位之前

`lib/ai-extract.ts` 的收據辨識 prompt 要求模型先在 `amount_digit_reasoning` 欄位逐字數清楚金額的零、再填 `amount_twd`,而且這兩個欄位排在 JSON 結構最前面,日期/分類/品項排在後面。

**背景**:實測發現手寫連續零(例如 30000 誤讀成 3000)是最常見也最傷的辨識錯誤,而「先轉錄整份收據所有文字、再抽取金額等各欄位」的版本無法解決這個問題——金額推理被埋在整份文件的轉錄裡,還是會出錯。改成「只獨立數金額的零、推理欄位排最前面」後,同一張困難測試圖從 0/3 答對提升到約 4/5。

**已測試並排除的替代方案**:
- 照片裁切去背景 / 轉正角度——A/B 測試證實對這個問題完全沒有影響,不要再往這個方向嘗試。
- 多次呼叫取多數決 / 針對金額做第二次交叉驗證——理論上可行,但需要多花 API 費用,目前沒有做,未來若準確度仍不夠可以考慮。

**已知限制**:即使用這個結構,仍量測到約 20% 的誤判率,且誤判時 AI 回報的 confidence 仍可能顯示 high。因此 `ConfirmForm.tsx` 的金額欄位下方保留常駐提醒,要求員工送出前對照收據核對金額——這道人工核對不能拿掉,不是過渡措施。
