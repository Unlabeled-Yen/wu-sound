# 規格:零用金管理＋薪資管理併入帳務管理

狀態:**待 Yen 確認**。來源=2026-08-15 Yen 口述需求(「把零用金管理和薪資管理合併在一起然後放到帳務管理系統裡面」+「薪資模組很簡單:員工是固定薪水,並有視案件和加班情況設立的獎金」)。

---

## 1. 現況(先講清楚才知道要動什麼)

### 1.1 三個模組現在的樣子

| 側欄項目 | 路由 | 實際內容 |
|---|---|---|
| 零用金管理 | `/boss/expenses` | 員工代墊審核清單:員工手機拍收據→AI 草稿→送出,老闆逐筆確認/退回 |
| 薪資結算 | `/boss/close` | **名不符實**——只有零用金月結:擋未審核→彙總已確認代墊→鎖定(`book_batches`)→匯出 CSV。固定薪資、獎金完全不在裡面 |
| 帳務管理 | `/boss/ledger` | 總帳。薪資/獎金靠老闆手動記帳(`kind=salary`/`bonus`);零用金靠「從薪資結算匯入零用金」按鈕把鎖定批次轉成 `kind=reimbursement` 分錄 |

### 1.2 資料流(單向鏈)

```
員工拍收據(expenses: draft)
  → 員工送出(submitted)
  → 老闆審核(/boss/expenses: confirmed/rejected)
  → 老闆月結鎖定(/boss/close: booked + book_batches)
  → 老闆手動按「匯入」(/boss/ledger: ledger_entries kind=reimbursement)

固定薪資/獎金:完全手動,老闆每月自己在 /boss/ledger/new 記 kind=salary、kind=bonus
```

### 1.3 既有但閒置的地基

- `user_pay_profiles` 表(月薪設定,生效日期制)——schema 建好,**零程式碼使用**
- `monthly_cost_rates` 表(月結凍結快照)——同樣閒置
- `ledger_entries.source_batch_id` → `book_batches`,匯入去重已在用

### 1.4 現況的問題

1. 「三個地方跑一圈」:審核在 A 頁、月結在 B 頁、入帳在 C 頁還要多按一次匯入——單向流程被拆成三個獨立入口。
2. 「薪資結算」四個字騙人:裡面沒有薪資,只有零用金。真正的薪資是散落在帳務的手動分錄,金額對不對、這個月發了沒,系統答不出來。
3. 忘記按「匯入」的月份,帳務首頁的支出就少一塊——靜默缺帳。

---

## 2. 目標形態

**側欄「財務」區從三項變一項:帳務管理。**
零用金與薪資變成帳務管理內的功能,不再是平行模組。

### 2.1 帳務管理的模式列(現有四個+一個)

```
[全部] [已收付] [應收款] [應付款] [月結]   ← 新增「月結」模式
```

- `?mode=payroll`(顯示名「月結」)承接原本 `/boss/close` + 薪資發放的整合畫面。
- 零用金審核清單(原 `/boss/expenses`)**維持獨立頁面**但從側欄移除,入口改為:
  - 帳務首頁既有的「N 筆零用金待審」pill(已存在,點了跳 `/boss/expenses`)
  - 月結模式內的阻擋卡連結(同現行 `/boss/close` 的阻擋卡)
  - 手機版底部導覽的「審核」分頁**維持不動**(員工送單後老闆手機審核是高頻動作,不能藏深)

### 2.2 月結模式(`/boss/ledger?mode=payroll`)畫面

單月視角(月份選擇器沿用現有 URL 驅動),三段:

```
┌─ 本月結算狀態 ────────────────────────────┐
│  未結算 / 已鎖定 yyyy-mm-dd / 已入帳        │
├─ 人員表 ──────────────────────────────────┤
│  姓名   固定月薪   獎金    代墊零用金   小計  │
│  吳智仁  65,000    +5,000   1,234     71,234│
│  許舒韶  32,000    0        4,983     36,983│
│  (獎金欄位:行內編輯,未鎖定前可改)            │
├─ 動作列 ──────────────────────────────────┤
│  [鎖定並寫入帳務]  [匯出 CSV]               │
└──────────────────────────────────────────┘
```

- **固定月薪**:來自 `user_pay_profiles`(終於啟用)。月結模式內提供「設定月薪」入口(每人一個生效日期制的金額,改月薪=新增一筆新生效日記錄,不改舊的)。
- **獎金**:視案件/加班,每月每人手填一個金額+一行備註(例:「恩光堂案獎金」)。不做計算規則——Yen 明講「視案件和加班情況設立」,是人為決定,系統只記錄不推算。
- **代墊零用金**:自動彙總該月 `confirmed` 的 expenses(即現行 `/boss/close` 的邏輯),唯讀。
- **阻擋條件**沿用現行:該月還有 draft/submitted 的零用金,不能鎖定。

### 2.3 「鎖定並寫入帳務」= 現行「鎖定」+「匯入」合併成一步

按下後在同一個動作內:

1. 建立 `book_batches`(沿用現有表與去重機制)
2. expenses 標記 `booked`(沿用)
3. **直接寫入 `ledger_entries`**,每人最多三筆:
   - `kind=salary` 固定月薪(有 pay profile 且金額>0 才寫)
   - `kind=bonus` 獎金(該月有填才寫)
   - `kind=reimbursement` 代墊彙總(有 confirmed 代墊才寫)
   - 全部帶 `source_batch_id`,重跑自動去重(沿用現有唯一鍵機制)
4. 沒有月薪 profile 的在職員工:**loud 提示**「XX 沒有設定月薪,本次不會寫入薪資分錄」,要老闆明確勾「我知道,繼續」才放行——不能默默跳過。

原本獨立的「從薪資結算匯入零用金」按鈕(`ImportBatchDialog`)保留一輪作為舊批次補匯入口,新批次不再需要它。

### 2.4 導覽調整

| 現在 | 改後 |
|---|---|
| 財務:零用金管理/薪資結算/帳務管理 | 財務:**帳務管理**(一項) |
| `/boss/expenses` | 路由保留,側欄移除(入口=待審 pill+月結阻擋卡+手機審核分頁) |
| `/boss/close` | 路由 redirect 到 `/boss/ledger?mode=payroll`(既有書籤/習慣不斷) |

## 3. 資料層變更

### 3.1 新增

- `payroll_bonuses` 表:`(id, batch_month date, user_id, amount_twd int >0, memo text, created_by, created_at)`,unique(batch_month, user_id)。獎金在鎖定前存這裡(可改),鎖定時轉成 ledger_entries。
  - 不直接寫 ledger 草稿的理由:鎖定前的獎金是「打算發」,不是帳;帳務裡不該出現會消失的數字。

### 3.2 啟用既有閒置表

- `user_pay_profiles`:新增設定 UI + 讀取邏輯(取生效日 ≤ 該月最後一天的最新一筆)。
- `monthly_cost_rates`:**本輪不動**(工時攤提是另一題,見 §5 不做清單)。

### 3.3 不改

- `expenses` 狀態機、員工手機端流程、AI 草稿——完全不動。
- `book_batches`、`source_batch_id` 去重機制——沿用。
- `ledger_entries` schema——不加欄位(salary/bonus/reimbursement kind 都已存在)。

---

## 4. 防靜默失效檢查點

1. 鎖定寫入是多筆操作:任何一筆失敗要**整批回報**(已寫入幾筆、失敗在誰、可安全重按——去重保證不重複),不准吞錯繼續。
2. 沒有 pay profile 的員工必須 loud 確認才跳過(§2.3.4)。
3. 已鎖定月份的獎金/月薪不可再改;要改=先有「解除鎖定」的明確動作(本輪先不做解鎖,規格列入 §6 待確認)。
4. 月結模式的人員表,「代墊零用金」欄在有未審核單時顯示「⚠ 尚有 N 筆未審核」而不是顯示不完整的合計數字——寧可不給數字,不給錯的數字。
5. `/boss/close` redirect 不做 silent 302 後直接消失:redirect 後的月結模式如果該月已有舊制鎖定批次,要正確顯示「已鎖定」狀態。

---

## 5. 明確不做(本輪)

- 工時/案件成本攤提(`monthly_cost_rates`)——另一題。
- 獎金計算規則引擎——Yen 明講獎金是人為決定,系統只記錄。
- 勞健保/扣款欄位——現況手動記帳沒這個粒度,等有需求再說。
- 解除鎖定/重開月結——先不做,做了會牽動去重與稽核。
- 員工端任何改動。

## 6. 待 Yen 確認

1. **模式名稱**:第五個模式叫「月結」還是「薪資」?(建議「月結」——它同時涵蓋薪資+獎金+代墊,叫薪資又會名不符實)
2. **獎金是否掛案場**:獎金分錄要不要選 site_id(掛到案件成本)?還是一律公司支出不掛案場?(現況手動記的獎金沒掛;建議先不掛,備註寫明案件名即可)
3. **薪資分錄的 occurred_on**:當月最後一天(同現行代墊匯入慣例)還是實際發薪日?(建議沿用當月最後一天,一致性優先)
4. **舊的手動薪資分錄**:過去手動記的 kind=salary 分錄不動、新制從下個月開始?還是要回溯?(建議不回溯,新制起點寫進 memo)
