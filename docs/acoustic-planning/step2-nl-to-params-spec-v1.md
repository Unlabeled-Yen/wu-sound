# 第二步規格 v1 — 人話轉參數(AI 只填輸入,不算輸出)(2026-08-03)

## 為什麼

雇主卡的不是「不會算」,是「嫌設定麻煩」。SPL 計算器目前要填九個欄位、陣列設計器要填目標寬度/觀眾席距離/涵蓋角,每開一次都要重新想一遍數字該給多少。這正是他自承「懶得報價」的同一種摩擦。

他真正會講的是這種話:

> 「磐頂主堂大概二十五米深、三百人,主要講道,偶爾敬拜團。」

這一步的任務就是把這句話翻成計算器的欄位,**然後停手**——數字由既有的確定性引擎算。

## 核心設計(對齊憲章)

延用 Phase 3 已驗證、並寫進 [ADR-0002](../adr/0002-ai-never-sets-price.md) 的同一個模式:

| 已驗證的模式 | 本步驟的對應 |
|---|---|
| AI 選品項,系統定價格 | **AI 填輸入參數,引擎算音壓與幾何** |
| 價格欄位在型別上就不存在於 AI 回傳結構 | **計算結果欄位在型別上就不存在於 AI 回傳結構** |
| 缺價 → 標「待設定售價」,總額不出數 | **參數沒依據 → 標「未指定」,不靜默塞預設值** |

三條硬規則:

1. **AI 不得回傳任何計算結果**。回傳結構裡沒有 `budgetDb`、`theoreticalMaxThrowM`、`coverageWidth3dbM`、`unityDist6dbM` 這些欄位,不是靠提示詞約束,是靠型別擋死。
2. **AI 不得靜默決定工程判斷值**。動態餘裕、安全餘裕、左右聲道疊加這類值,若使用者的描述裡沒有依據,AI 必須回傳 `null` 並說明,由 UI 顯示「未指定,沿用預設 12dB」,不得自己填一個看起來合理的數字。
3. **一律預填,絕不自動送出**。AI 填完欄位後停在表單上等人確認,使用者可逐欄改。不做「一句話直接出答案」。

## 介面

在兩個計算器頁面上方各加一塊輸入區(沿用報價頁「AI 選設備」那塊的視覺語言,含語音輸入按鈕——`QuoteEditor.tsx` 已有可複用的 `SpeechRecognition` 實作)。

流程:輸入描述 → 按「幫我填參數」→ 欄位被預填 + 每欄標示依據 → 人確認/修改 → 按原本的計算按鈕。

## 資料契約

### SPL 預算計算器

AI 回傳(欄位名對齊 `SplCalculatorForm.tsx` 現有 state):

```
{
  "fields": {
    "targetSplDb":        { "value": 數字|null, "basis": "依據原話的哪一段|null" },
    "checkDistanceM":     { "value": 數字|null, "basis": ... },
    "stereoSumDb":        { "value": 數字|null, "basis": ... },
    "dynamicHeadroomDb":  { "value": 數字|null, "basis": ... },
    "safetyMarginDb":     { "value": 數字|null, "basis": ... }
  },
  "speaker_hint": "使用者若提到型號,原樣寫在這|null",
  "unclear": ["描述中沒講、無法推斷的項目,人話列出"]
}
```

**不在契約內**(AI 不得填,由既有機制處理):`maxSplDb`、`refDistanceM`、`sensitivityDb`、`ampPowerW`——這四個是器材規格,只能來自品項庫或人工輸入,見[第三步](step3-spec-data-spec-v1.md)。`speaker_hint` 僅供 UI 反白對應的品項供人點選,**不自動選定**。

### 陣列設計器(Auto Mode)

```
{
  "fields": {
    "targetWidthM":   { "value": 數字|null, "basis": ... },
    "audienceDistM":  { "value": 數字|null, "basis": ... },
    "speakerCovDeg":  { "value": 數字|null, "basis": ... }
  },
  "unclear": [...]
}
```

`forceQty`、`spacingOverride`、`qtyOverride` 是人工覆寫用的,**AI 不得碰**。

### 型別落點

新增 `web/lib/ai-planning-params.ts`,對外只輸出上述兩個型別與一支解析函式。比照 `lib/ai-quote.ts`:`server-only`、雙供應商(有 `ANTHROPIC_API_KEY` 走 Anthropic,否則 Kimi)、`temperature: 0.1`、失敗回 `{ error }` 不拋。

## 缺值與失敗的處理(loud)

| 情況 | 行為 |
|---|---|
| 某欄 `value: null` | 欄位維持既有預設值,但下方以警示色標「AI 無法從描述判斷,沿用預設 X」 |
| `unclear` 非空 | 表單上方列出「這些沒講到,我用了預設值:…」 |
| AI 呼叫失敗 | 明確顯示錯誤,表單保持原狀,**不得悄悄跳過** |
| AI 回傳非法值(負數、非數字、超出合理範圍) | 該欄視同 `null`,並在錯誤區標明「AI 回傳了無法採用的值」 |

合理範圍檢查(確定性,不由 AI 判斷):`targetSplDb` 60–120、`checkDistanceM` 0–200、餘裕類 0–30、`targetWidthM`/`audienceDistM` 0–200、`speakerCovDeg` 0–360。超出即拒收。

## 驗收條件

| ID | 條件 | 方式 |
|---|---|---|
| P-01 | 描述含明確距離(「二十五米深」)→ `checkDistanceM`/`audienceDistM` 正確填入 25 | auto(固定案例) |
| P-02 | 描述完全沒提餘裕 → 三個餘裕欄皆 `null`,UI 顯示沿用預設,**不得出現 AI 自行編造的數字** | auto |
| P-03 | AI 回傳結構含任何計算結果欄位 → 被型別/解析層丟棄 | auto |
| P-04 | AI 呼叫失敗 → 畫面出現錯誤訊息,欄位不變 | browser(斷網或改壞金鑰) |
| P-05 | 預填後不自動計算,需人按原按鈕 | browser |
| P-06 | 每個被填的欄位都看得到依據 | browser |
| P-07 | 固定描述連跑 5 次,關鍵數值欄一致 | auto(比照收據辨識的穩定度測法) |

P-07 的門檻先設「距離、目標音壓兩欄 5/5 一致」。若達不到,先降低模型自由度(縮短提示詞、明確禁止推論),不要加重試。

## 不做

- 不做「一句話直接得到答案」。中間的人工確認是刻意保留的。
- 不讓 AI 選定喇叭型號。它只能提示,選定是人的動作(這條與 ADR-0002 同源:AI 提議、人與確定性系統定案)。
- 不做多輪對話式追問。第一版只做一次性解析,`unclear` 用列出的方式讓人自己補。
- 不把解析結果存進資料庫。這是一次性的填表輔助,沒有稽核價值。

## 成本

每按一次「幫我填參數」= 一次 API 呼叫。純文字、無圖片,成本遠低於收據辨識。使用者不按就不花錢。
