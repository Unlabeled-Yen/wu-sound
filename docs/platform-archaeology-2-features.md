## 帳務(已於本輪深度考古)

見 [ledger-master-spec.md](./ledger-master-spec.md) 第 2-3 節(狀態機、業務規則)。
摘要:五本帳簿看板(客戶/廠商/零用金/薪資/老闆個人)→ 明細頁(可篩選)→ 應收應付
→ 待開發票 → 月結鎖定(整月零用金彙總成一筆入帳,案場/單筆明細在此消失)。

## 報價系統

**新增報價單**:填客戶名 + 選填套組 → 若選套組,把 `bundle_lines` 材料化複製
成 `quote_lines`(抓當下品項庫售價)→ 建立 `draft` 狀態報價單。

**編輯明細**:單一 action-based endpoint(`add/update/delete`)。挑選品項庫品項時
自動帶入名稱/單位/售價;**編輯單價存檔時有個「存回價目表」勾選框,預設打勾**
(只要這行原本連品項庫)。

**AI 建議配置**:老闆打字或用瀏覽器語音輸入需求描述 → 送品項庫品名清單
(不含價格)給 AI(Claude 優先,Kimi 備援)→ AI 回傳建議品項+理由 →
系統比對回真實品項庫 row,對不到的變自由行(自動待補價)。

**送出/成交/流單**:狀態下拉四選一(draft/sent/won/lost),唯一規則是切到
`sent` 前所有行要有單價,其餘轉移完全自由。

**列印/匯出**:列印頁算稅、CSV 匯出**不算稅**(兩者總價會對不上)。

**標配套組**:獨立範本庫,老闆維護「適用情境+內部備註」,新建報價單時選填
帶入,之後套組跟報價單互不影響。停用是軟刪除(`active=false`)。

## 設備庫存

**登記新設備**:填基本資料 → 固定 `in_storage`,不寫移動紀錄(新增不算移動)。

**移動設備**(老闆專用):選目的地狀態+案場 → 驗證(僅檢查地點與狀態一致)→
更新 + 寫一筆 `equipment_movements`。**四個狀態可以任意互轉,包括已淘汰的
設備透過這個功能直接「復活」回在庫/在場**。

**淘汰設備**:確認對話框宣稱「無法直接還原」,但如上,移動功能可以繞過這句話。

**員工端**:純唯讀清單(自動排除已淘汰),沒有任何寫入按鈕。

## 專案管理與現場

**案場管理**(老闆):建立/改名/設類別/設客戶名/停用(停用前檢查有無設備仍在場)。

**工作記錄**(員工):選案場 + 一句話 + 施工前後照片(或填無照片原因)→ 存檔,
純記錄,無工時。**老闆端唯讀展示,無編輯/刪除入口。**

**打卡**(員工):上班/下班兩顆按鈕。**下班打卡後 UI 自動展開「今天去了哪個
案場」的勾選區**——這個勾選寫的是 `day_site_allocations`,跟打卡本身
(`clockins`)是兩張獨立的表,只是 UI 上銜接在一起。可補打卡(需填原因),
**沒有編輯/刪除既有記錄的入口**。

**老闆看打卡**:月曆式表格,前端算好每人每日工時**只供顯示**,不寫回任何表。
下方另有「案場歸屬編輯器」可老闆代填/改任何人任何一天的案場歸屬——
**但畫面上顯示的工時數字,存檔時完全不會被送到後端**,`hours` 欄位形同虛設。

## 使用者、權限、LINE、voice-lab

**登入**:姓名 + 4 位數 PIN(bcrypt 驗證)→ 自簽 cookie,14 天內完全不查 DB。

**使用者管理**(老闆):建立/改名/停用/重設 PIN。**角色只能在建立當下選定,
之後無法從 UI 把 staff 升成 boss(或反過來)。**

**權限判斷**:三層各自檢查,無統一 middleware——layout 層集中(乾淨),
server actions 層部分集中(只有 users 模組有共用 `assertBoss()`),
**API route 層完全散落,同一段 `if (session.role !== 'boss')` 判斷在 30+
支檔案裡各自重複貼上**。

**LINE 整合**:
- Webhook 收文字「綁定 123456」→ 完成帳號綁定(6 位數碼,10 分鐘 TTL)
- 收文字「上班」/「下班」→ 直接寫入打卡
- 收圖片 → 建立零用金收據草稿(跟 App 拍照走同一套底層邏輯)
- 老闆/員工之間的審核結果互相推播通知(失敗只記 log,不擋主流程)

**voice-lab 語音助理**:不是記帳工具,是**現場口述→結構化派工/工作記錄**的
介面。員工口述,LLM 產生建議動作(建任務/記筆記)提案,**LLM 本身沒有直接
寫入權限,一定要人工按確認才真的落地**。目前是 Lab 2(文字對話已可用)+
Lab 3 部分(語音辨識),Lab 4(真正手機端語音擷取+離線佇列)完全未開始。
`voice-lab-chat` 頁面刻意不掛進任何導覽選單,是實驗頁,非正式產品入口。
**沒有角色/案場區分,任何登入者都能對所有案場下指令。**

## 聲學計算工具

**SPL 預算計算器**:輸入喇叭極限音壓+目標音壓+場地距離(可從品項庫帶入
規格)→ 算出建議最遠涵蓋距離,連同一串「未計入現場變因」的警語。

**陣列設計器**:輸入場地寬度/觀眾距離/喇叭覆蓋角 → 算建議喇叭數量/間距/
張角,五個分頁對應反解不同未知數。這是對第三方商業軟體的黑盒逆向工程
重製(2081 組 golden 資料驗證過),**唯一風險是「手動覆寫建議值後重算」
這條路徑,作者自己註記是推論、未經原軟體實測驗證,但已經是最常用的互動
路徑之一。**

兩個工具都是純前端計算,不落地,也不回寫報價系統(算完的建議數量要手動抄
到報價單)。

## 標案監測

**資料進度板**:開發者用的資料完整度監控頁(各資料來源的覆蓋率/狀態)。

**標案監測(核心頁)**:篩選天數/金額級距/案件性質/流標重招池 → 顯示標案
卡片清單,含機關過去獨標率(樣本不足時只給區間、不給比率,避免誤判)。

**機關經營名單**:近 3 年發過音響類標案的機關排行榜,判斷哪些機關值得
長期經營、哪些已沉寂——但這頁**沒有進任何導覽選單**,只能從監測頁內部
連結點進去。

全部三頁都是純渲染器,即時打外部服務 API,無本地儲存,無寫入功能。
