## 為什麼

### 記帳樣本再解剖(2026.7 分頁,補 phase4-spec 未記錄的發現)

phase4-spec 已記錄:`#REF!` 兩處、「不知道為什麼有多的 21,014」、代墊 4,983 與明細加總 4,938 不符、自由文字欄混雜。本次重讀原表,再確認三件事:

1. **老闆在用兩欄追「現金」與「應收應付」兩本帳**:收入區 D 欄=已入帳、E 欄=待收(例:斗六旌旗 407,715 在 E 欄);支出區 D 欄=已付、E 欄=待付,F54 直書「待付款金額」。應收應付是他的真實心智模型,不是流水帳。
2. **轉帳手續費混在金額裡**:租金 13,015、停車 2,015、薪資 65,015——大量「+15」尾數,帳面數與實付數無法區分。
3. **藏在公式裡的手改數字**:`E12 =657715-250000`,25 萬調整無任何說明;借款 1,062,811 列在收入區灌水營收;股票投資 50 萬、老闆健檢、零用金等個人項混在公司支出。

### 新需求一:時數計入專案支出(2026-08-14 Yen 提出)

平台已有打卡系統 → 花在專案的時數可被計算 → 時數成本應計入各專案的支出結構。
**已確認前提:員工為固定月薪+獎金制;每人月薪數字老闆之後給。**

### 新需求二:多維報表(2026-08-14 Yen 同日提出)

Yen 原話:「當數字資料進去帳務系統時,我可以透過 UI 轉成專案(每個專案的收入支出)、不同性質案件類別(像是固定安裝、活動收入/支出)、公司年度季度相關專案的所有收入及支出。」

定調為「**記一次帳、多維度看**」:每筆帳入帳時只標記一次(掛案子),之後從三個正交軸任意聚合——

| 軸 | 回答的問題 |
|---|---|
| 專案 | 這個案子從頭到尾賺多少(整案期,不被月/季切割) |
| 案件類別 | 我的生意組成:固定安裝 vs 活動 vs 維修各佔多少、毛利各如何 |
| 時間 | 這個月/季/年公司整體收支如何 |

**類別掛在案子上,不掛在帳目上**:一案一性質,帳目掛案子即自動繼承類別。入帳者永遠只做「選案子」一個動作,標記負擔不增加,卻多出一整個分析軸。同一客戶既有安裝又辦活動 → 開兩個案子(慣例)。

## 範圍

**做(第一批)**
- 輕量應收應付:`receivables` 一張「約定」表,金流帳目可掛約定,未結金額派生
- 待開發票清單:`invoice_status='to_issue'` 集中頁,逾期變色
- 定期帳範本:每月 lazy 產「草稿」帳目,老闆確認才生效;**不用 cron**(排程靜默失敗風險),開當月帳務頁時即時補產
- 月結轉檢核 + 對帳 lite:月視圖顯示期初/期末餘額鏈;老闆月末手填銀行實際餘額,差額不為零整頁亮紅
- 手續費獨立欄:`fee_twd`,帳面/實付分離,報表小計
- **報表中心** `/boss/report`:期間選擇(月/季/年)× 維度切換(總覽/案件類別/專案/客戶),任何數字可下鑽到帳目明細;營收自動排除借款/業外;每個視圖含未歸類殘差行
- site_id 地基:`ledger_entries`、`quotes` 加選填案場
- 案件類別:`site_categories` 老闆自管清單 + `sites` 掛類別與客戶欄(一案一性質慣例)
- 下班歸屬一問:下班打卡多答「今天去了哪個案場」(可多選、可跳過)
- 工時配對:每對 in→out 相加(open-questions Q1 暫定口徑),未配對 loud
- `user_pay_profiles` 月薪設定表(生效日期制,boss-only)

**做(第二批,等月薪數字)**
- 當月成本時薪計算與月結凍結快照
- 專案損益頁:收入 − 直接成本 − 人力分攤 = 專案毛利

**不做**
- 完整複式簿記(1+3 人規模是過度工程)
- 權責制認列:主視圖一律現金制(對齊老闆現行心智模型),以「在手應收/應付」行補正,見計算規則
- 「某季的專案損益」混血報表:專案軸與時間軸正交,專案損益永遠整案期呈現
- B 路薪資自動化(ADR 0005 不動;本 spec 的月薪設定只供損益估算,不碰實發)
- customers 正規化表:先以 `sites.customer_name` 文字欄擋著,規模化階段再正規化
- 銀行自動抓帳(只接受老闆手動下載 CSV 上傳,且屬規模化階段)
- 多帳戶、電子發票串接(規模化階段)

## 資料模型(遷移草案)

### `receivables`(應收應付約定)

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid pk | |
| direction | enum `receivable_direction`('receivable','payable') | 應收 / 應付 |
| party | text not null | 對象 |
| site_id | uuid nullable fk → sites | 掛案場(可空) |
| total_amount_twd | integer > 0 | 約定總額 |
| memo | text | |
| status | enum('open','closed','voided') | closed 由結清動作寫入;未結金額一律派生,不存欄位 |
| created_by / created_at / updated_at | | 沿用專案慣例 |

- `ledger_entries` 加 `receivable_id uuid nullable fk`:一筆金流可掛一筆約定
- 未結金額 = `total_amount_twd − SUM(掛此約定且 active 的金流)`;DB view 提供,前端不自己加
- 超收/超付(SUM > total)→ loud 顯錯,不靜默吞

| 欄位 | 說明 |
|---|---|
| id / name / active | 清單由老闆用他的語言定義(如:固定安裝工程、活動、維修保養);系統不預塞、不發明分類 |

| 欄位 | 型別 | 說明 |

| 欄位 | 型別 | 說明 |

| 欄位 | 說明 |
|---|---|
| name / direction / kind / amount_twd / fee_twd / party / is_external / site_id | 產草稿時複製 |
| day_of_month | 每月幾號入帳(草稿的 occurred_on) |

### `day_site_allocations`(每日案場歸屬)

| 欄位 | 說明 |
|---|---|
| user_id / worked_on date / site_id fk | |
| hours | numeric nullable;空 = 該日配對工時在所選案場間均分 |

- 下班打卡時寫入;員工當日可改,老闆隨時可改,改動寫 audit_log
- 該日無任何列 = 未分攤(內勤/庫房池),報表明列,**絕不硬塞進專案**

### `user_pay_profiles`(月薪設定,生效日期制)

| 欄位 | 說明 |
|---|---|

## 計算規則

1. **工時配對**:同一人同一日,每對 in→out 相加為當日工時。未配對打卡(有進無出、有出無進)→ 該日不計入且 loud 列出(承 open-questions Q2 暫定:擋月結)。
2. **當月成本時薪** = 該員工當月生效月薪 ÷ 當月總配對工時。**比例分攤,不用固定分母**——恆等式:Σ各案分攤 + 未分攤池 = 月薪,每塊錢有去向。閒月每小時成本高是固定薪資結構的真相,報表如實呈現。
3. **案場人力分攤** = 該案場歸屬工時 × 當月成本時薪。
4. **獎金**:記帳時掛 site_id → 該案直接成本;未掛 → 未分攤池。不進時數分攤。
5. **專案損益** = 收入(site) − 直接成本(site) − 人力分攤(標明「估算口徑」)。
6. **人力分攤絕不寫入 ledger_entries**——薪資已以實發現金入帳,再入分攤即重複計支出。分攤是報表層計算視圖,帳本永遠只記真實金流。
7. 5% 稅額照舊 `round(amount/21)`;報表營收自動排除 `kind in ('loan')` 與業外項(`investment`,`health` 列「個人/業外小計」)。
8. **認列口徑:全視圖現金制**。大工程施工月與收款月會分離(如斗六旌旗 9 月完工、款在應收),純現金制會讓季度比較失真;對策不是權責制,而是每個期間視圖旁固定一行「**在手應收 $X / 在手應付 $Y**」(來自 receivables 未結派生)。老闆看到「這季收 80 萬,另有 40 萬做完未收」,兩個數字都真。
9. **殘差行恆等式(每個維度視圖強制)**:Σ各分項 + 未歸類行 = 帳本總數。未歸類行明示「另有 N 筆共 $X 未掛案場/未設類別」。視圖寧可露醜,不准默默少算。月結檢核加一條:`kind='project'` 且無 site_id 的帳目 loud 列出。
10. **專案軸與時間軸正交**:專案損益一律整案期呈現,不受期間篩選切割;期間視圖不提供「單案在此期間的損益」混血數字。
11. **報價對照**:案子若連結報價單(`quotes.site_id`),損益頁並列「報價預估毛利% vs 實際毛利%」。第一批先出粗毛利(收入−直接成本),第二批含人力分攤後為完整口徑。此對照未來餵 AI 報價的歷史脈絡注入(flywheel 待辦第一條)。

## 憲章對齊

- **無靜默失效**:未配對打卡、未分攤時數、草稿未確認、餘額核對差額、超收超付——全部 loud,不靜默吞
- **殘差行恆等式**:所有維度視圖 Σ分項+未歸類=帳本總數;報表寧可露醜,不准默默少算(tender-radar 教訓的報表層應用)
- **AI 永不直接入帳**:整個第一/二批零 AI;AI 副軌只產草稿、人確認才入帳(建議屆時立 ADR 0008,對齊 ADR 0002「AI 絕不出價」精神)
- **DB 算總數**:未結金額、餘額鏈、分攤合計全走 SQL,前端不自己加
- **隱私**:月薪與分攤金額 RLS 擋在資料層,不是前端藏
- **可追溯**:receivables 結清、草稿確認、歸屬改動、月薪異動全寫 audit_log
- **ADR 0005 不動**:實發薪資仍老闆手填;本 spec 只讀月薪設定做估算報表
