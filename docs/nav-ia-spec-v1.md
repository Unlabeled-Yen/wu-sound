### hidden 項目

`NavItem.hidden` = 不畫在側欄,但**仍參與比對**。人在價目表時,側欄該亮的是「報價系統」那一列、
桌機標題該顯示「報價系統 / 價目表」。若直接把項目從結構裡刪掉,這兩件事都會默默指錯——
不會報錯、只會顯示錯的資訊,所以用旗標而不是刪除。

## 2. 頁內分頁(把數頁併成一頁的視覺)

兩組:

- 報價系統:`報價系統 ┃ 標配套組 · 價目表`。分隔線把「產出」與「資料來源」分開。
- 聲學計算:`SPL 預算計算器 ┃ 陣列設計器`。

**分頁背後仍是各自獨立的路由**,不是前端狀態切換。理由:
1. 陣列設計器帶畫布互動、程式碼重;SPL 只需要喇叭+擴大機資料,陣列設計只需要喇叭。
   合成單一路由等於每次都載入兩份資料與兩份程式碼。
2. 上一頁按鈕、深層連結、書籤都要能用。

報價系統三頁用 Next.js 路由群組 `app/boss/(quote-system)/` 共用 layout,
**網址完全沒變**(`/boss/quotes`、`/boss/bundles`、`/boss/catalog`)。

例外:報價單列印頁 `/boss/quotes/[id]/print` 不顯示分頁列(`PageTabs` 的 `hideOn`)——那頁要印給客戶。

## 3. 標案監測:頁面鎖一個視窗

- 固定區:標題、命中件數、天數切換、池子切換、價格×性質分佈矩陣。
- 捲動區:標案卡片清單,底部漸層提示「下面還有」。
- 頁面總高度 = 一個視窗,不隨命中件數改變。

**手機例外**:分佈矩陣在手機上跟著清單一起捲。手機固定的話清單只剩 166px,不到一張卡的高度——
量過才發現的,不是猜的。桌機維持固定(地圖不該在你走動時捲走)。

### ViewportLock 的量測方式

`web/app/_shared/ViewportLock.tsx`(原本在 catalog 底下,現在共用)。

舊版用 `window.innerHeight` 減一個寫死的常數(`32 + 14`,桌機 padding 的總和)。桌機剛好對,
手機少扣了 96px 的底部分頁列,清單最後一列會被蓋住——典型的靜默失效。

新版往上走每一層祖先,各自算「這層允許我延伸到的最低點」= `min(這層底邊, 視窗底) − 這層的 padding-bottom`,
取最小值。padding-bottom 正是版面用來替固定元件預留的空間,照著扣就會停在正確位置,沒有魔術數字。
