## 資料語意鐵律(不可違反,視覺怎麼調整都要守住這幾條)

1. **「已收付」的錢跟「應收未收」的錢,絕對不能合成同一個數字。**
   系統是現金收付制(不是複式記帳),一筆錢先被記成「應該收」、之後實際收到又記一次,會讓收入被算兩遍。這頁把兩者放在同一個視覺系統裡(比例條、混合列表),是為了讓使用者一眼看懂全貌,但底層資料、加總邏輯必須保持分離。畫面上任何地方要標「已收 X + 未收 Y」,不能只寫一個模糊的合計。

2. **「帳面淨額」跟「實收實付淨額」是兩個不同的數字,必須同時可見,不能只留好看的那個。**
   兩者的差距(帳面賺錢但現金沒進來)本身就是這個頁面最重要的警訊,是老闆真正在意的資訊。

3. **比例條(已收/未收)的寬度是「這一欄自己的 100%」,不能被拿來跟另一欄的比例條比大小。**
   收入欄的比例條跟支出欄的比例條,滿寬各自代表不同的金額基準——大小比較的責任在淨額帶跟大數字,不在比例條的長度。

4. **未收/未付的視覺標記,顏色不能是唯一的區分方式。**
   目前用「斜紋 vs 純色」做第二編碼,不只是深淺色差——色盲安全是硬性要求。

5. **已結算的分錄如果混排在「全部」模式的列表裡,必須有明確的「已收/已付」標記,不能只靠「沒有未收未付標籤」來暗示已結算。**
   這是這輪剛修過的真實 bug:使用者看列表時,未收/未付項目有顯眼黃色警示牌,已結算項目原本什麼標記都沒有,結果被誤讀成「完全沒有已收付的單」。對稱性很重要。

## Overview

帳務模組首頁,取代了原本四個分散頁面(帳簿看板 / 帳目明細 / 應收應付 / 待開發票)。使用者是公司唯一的老闆,行動裝置與桌機都會用,桌機用得多。核心任務:一眼看懂「這個月/現在的錢況」,並能篩選、下鑽、直接動作(記一筆、編輯、作廢、結清應收應付)。

四種檢視模式(URL 用 `?mode=` 切換):
- **全部**(預設,無 `mode` 參數):帳面視角,已收付分錄 + 未結應收應付混合呈現
- **已收付**(`mode=settled`):只看錢真的動過的
- **應收未收**(`mode=receivable`):只看還沒收到的
- **應付未付**(`mode=payable`):只看還沒付的

## Layout

### 桌面(≥1024px,Tailwind `lg:` breakpoint)

```
┌─────────────────────────────────────────────────────────┐
│ 標題「帳務」                              [記一筆] 按鈕    │
├─────────────────────────────────────────────────────────┤
│ 待處理提示 pill 列(有才顯示,無資料時整列不出現)          │
├─────────────────────────────────────────────────────────┤
│ 模式切換 4 個 pill + 月份導覽(全部/已收付模式才顯示月份)  │
├─────────────────────────────────────────────────────────┤
│ 篩選列:歸屬 / 分類 / 發票 / 內外帳 下拉 + 套用按鈕        │
├─────────────────────────────────────────────────────────┤
│ 淨額帶:帳面淨額 + 實收實付淨額,並排,全寬                 │
├──────────────────────┬──────────────────────────────────┤
│ 收入欄首統計(固定高)  │ 支出欄首統計(固定高)              │ ← 兩欄同高,grid 對齊
│ (帳面收入/比例條/排行)│ (帳面支出/比例條/排行)            │
├──────────────────────┼──────────────────────────────────┤
│ 收入列表(固定高,內部捲動)│ 支出列表(固定高,內部捲動)     │ ← 兩欄同高,grid 對齊
└──────────────────────┴──────────────────────────────────┘
```

「應收未收」「應付未付」模式底下版面改成單欄(不分收入支出),月份導覽消失(見下方 States 章節)。

### 手機(<1024px)

**目前是最弱的一塊,還沒真正為手機重新設計過**,只是桌面版的元件在窄螢幕下自然換行/堆疊:
- 篩選列從一排 4 個下拉變成兩排、每排 2 個
- 收入欄、支出欄從左右並排變成上下堆疊(先收入整欄、再支出整欄)
- 淨額帶的兩個數字維持並排,螢幕 375px 寬勉強放得下,再窄會擠
- 固定高度捲動面板(560px)在手機直式畫面裡佔比過高,一頁塞不下几個東西就要滑很久

**這塊需要你重新設計,不是微調。** 可以考慮的方向(未定案,你來判斷):月份導覽跟篩選收進一個可收合的抽屜、欄首統計用更精簡的橫向卡片、列表面板高度用 `vh` 相對值而不是固定 560px。

## Design Tokens Used

專案是深色玻璃感(dark glass)設計語言,定義在 `web/app/globals.css`,前綴 `--nm-*`。**不要引入新的色彩系統或字體**,這頁要跟平台其他頁面（設備庫存、報價系統等)視覺一致。

### 色彩

| Token | Value | 用途 |
|---|---|---|
| `--nm-bg` | `#0f0f11` | 頁面底色 |
| `--nm-text-primary` | `#f0f0f2` | 標題 |
| `--nm-text-body` | `#e4e4e7` | 主文字、金額數字 |
| `--nm-text-secondary` | `#9c9293` | 次要文字、標籤說明 |
| `--nm-text-muted` | `#6d6e73` | 弱化文字、輔助連結 |
| `--nm-text-faint` | `#5a5b60` | 更弱(placeholder 等) |
| `--nm-success` / `--nm-success-glass-text` | `#7ecf9d` / `#a9e3c1` | 收入、已收付、正向淨額 |
| `--nm-danger` / `--nm-danger-glass-text` | `#e07a7a` / `#e5a0a0` | 支出、負向淨額、作廢動作 |
| `--nm-warning` / `--nm-warning-glass-text` | `#d9b56b` / `#e7ca8c` | 未收/未付、待處理、AI 沒把握 |
| `--nm-border-hair` | `rgba(255,255,255,0.05)` | 表格列分隔線 |
| `--nm-border-glass` | `rgba(255,255,255,0.17)` | 卡片邊框 |

**色彩語意是固定的,不要挪用**:綠色永遠是「收入/已完成/正向」,紅色永遠是「支出/負向」,黃色永遠是「還沒處理/需要注意」。這不是這頁自己發明的,是整個平台(設備維修中、報價待送出、零用金待審⋯)共用的語言。

### 形狀 / 圓角

| Token | Value |
|---|---|
| `--nm-radius` | `13px`(按鈕、輸入框) |
| `--nm-radius-lg` | `20px`(卡片、面板) |
| `--nm-radius-xl` | `28px` |
| `--nm-radius-pill` | `999px`(pill 標籤、模式切換按鈕) |

### 表面材質(玻璃層次,越靠近底片模糊度越高)

| Class | 用途 | 視覺 |
|---|---|---|
| `.nm-raised` | 一般卡片(列表面板、欄首統計卡) | 半透明深灰 + 16px 模糊 + 玻璃邊框 |
| `.nm-raised-sm` | 數字卡(淨額帶) | 更深底色 + 內陰影,文字有輕微陰影提高可讀性 |
| `.nm-inset` | 凹陷面板(搜尋列背景) | 更暗、內陰影 |
| `.nm-pill` + `.nm-pill-warning` / `.nm-pill-muted` / `.nm-pill-neutral` | 狀態標籤 | 11.5px 字、999px 圓角 |
| `.nm-btn` / `.nm-btn-solid` | 次要/主要按鈕 | 玻璃灰底 / 實心白底 |

### 字級

沒有獨立定義字級 token,目前用 Tailwind 任意值(如 `text-[13px]`)。主要字級:
- `text-2xl`(24px):淨額帶大數字、欄首大數字
- `text-[16px]`:列表項金額
- `text-[14px]`:列表項標題(分類/對象名稱)
- `text-[13px]`:次要文字、標籤、篩選下拉
- `text-xs`(12px):排行小條、金額標籤、時間戳

字體:`Noto Sans TC` / `PingFang TC`(中文優先)。

## Components

### 1. 模式切換 pill 列

| Variant | 說明 |
|---|---|
| 選中 | `.nm-btn-solid`(實心白底黑字) |
| 未選中 | `.nm-btn`(玻璃灰底) |

四個選項:全部 / 已收付 / 應收未收 / 應付未付。圓角 `999px`,padding `4px 14px`,字級 13px。

### 2. 淨額帶(net band)

全寬 `.nm-raised-sm` 卡片,內部 `flex flex-wrap gap-8` 並排兩組數字(標籤 13px 灰 + 數字 24px 粗體,顏色依正負號決定綠/紅)。**兩個數字永遠同時顯示,不可只留一個。**

### 3. 欄首統計卡(ColumnHeader)

固定高度 **260px**(`.nm-raised` + `p-4`),`flex flex-col` 排列三段:

1. **大數字**:標籤「帳面收入/帳面支出」+ 24px 粗體金額
2. **比例條**:2.5px 高、999px 圓角,已收付段實色填滿、未收未付段用 45° 斜紋(`repeating-linear-gradient`)+ 左邊界虛線分隔。下方左右各一個可點連結,顯示「已收/已付 $X」「未收/未付 $Y」,點擊切換對應模式。
3. **排行**(可為空,超過 3 項自動併成「其他」):每行是「名稱(固定寬度截斷)+ 迷你橫條(1.5px 高)+ 金額」,可點,連結會套用歸屬(收入按專案)或分類(支出按分類)篩選。排行區用 `flex-1 min-h-0 overflow-y-auto` 吃掉卡片剩餘高度,理論上 4 行以內用不到內部捲動。

**已知的視覺弱點,值得你重新設計**:比例條目前只有 2.5px 高,配色又是同色系深淺(斜紋 vs 純色),在小螢幕或快速掃視時辨識度不夠高。排行的迷你橫條(1.5px 高、最大寬度沒有限制在合理範圍)也偏弱。這整塊「數字 + 比例條 + 排行」的資訊密度其實蠻高的,值得用更有層次的方式重新設計,只要不違反上面的資料語意鐵律。

### 4. 列表面板

固定高度 **560px**、`overflow-y-auto`,兩欄(收入/支出)在桌機並排、手機堆疊。列表內容是**混合列表**(「全部」模式下):未結約定排最上面、已結分錄接著照日期排。

- **已結分錄行**(`LedgerRowMobile` 元件,`web/app/boss/ledger/LedgerRowMobile.tsx`):方向箭頭 + 分類 + 金額,下方 pill 列(全部模式下含綠色「已收/已付」標記、內外帳、待確認、發票狀態),備註,底部編輯/作廢連結
- **未結約定行**(內嵌在 `AllColumnList`,`page.tsx` 內):對象 + 未結金額(超收會標紅),歸屬 + 約定總額,黃色「未收/未付」pill,結清/作廢按鈕(`StatusButtons` 元件)

兩種行目前用**同一種卡片外觀**(`.nm-raised rounded-2xl p-3.5`),靠 pill 顏色跟有無「已收/已付」標記區分。這是刻意的一致性選擇,但你可以評估是否要讓兩種行在視覺上有更明確的形狀差異(例如未結約定的卡片邊框用不同處理)。

### 5. 待處理提示 pill

只在有資料時顯示,四種:待開發票(黃)、AI 待確認(黃)、超收/超付(紅底)、零用金待審(灰),點擊直接套用對應篩選/導向。

## States and Interactions

| 元素 | 狀態 | 行為 |
|---|---|---|
| 模式切換 pill | 點擊 | 導向對應 `?mode=` URL,Server Component 重新渲染整頁 |
| 月份導覽「← 上月/下月 →」 | 點擊 | 導向 `?month=YYYY-MM`,只在「全部」「已收付」模式顯示 |
| 應收未收/應付未付模式 | 進入 | 月份導覽整塊消失(這是刻意的——應收應付是「現在的餘額」不是「某期間的流水」,不受月份篩選) |
| 篩選下拉 | 改變後點「套用」 | 送出 GET 表單,非即時篩選(無 JS 也能動作,SSR 友善) |
| 比例條「已收/未收」文字 | hover | `underline`,點擊切換模式 |
| 排行列 | hover | `opacity-80` + transition,點擊套用篩選 |
| 淨額 / 帳面收入支出數字 | 正負號 | 綠(≥0)/ 紅(<0),無中間態 |
| 「顯示已作廢」連結 | 點擊 | 只在「已收付」模式,切換到顯示已作廢分錄(此時不計入合計,並有黃色提示條說明) |
| 列表面板 | 內容超過 560px | 面板內部出現滾動軸,面板本身不長高 |
| 結清/作廢按鈕(應收應付) | 點擊 | `fetch` PATCH,成功後 `window.location.reload()`(非樂觀更新) |
| 作廢分錄(VoidDialog) | 點擊「作廢」 | 彈窗兩步驟:填原因 → 確認,見 `web/app/boss/ledger/VoidDialog.tsx` |

## Edge Cases

- **空狀態**:列表面板顯示「沒有紀錄」置中文字(13px 灰);待處理提示整列在無資料時完全不渲染,不留空白區塊
- **金額 $0**:正常顯示 `$0`,不特殊處理,但要跟「查詢失敗」明確區分(見下)
- **查詢失敗**:整個內容區塊(不含篩選列)替換成紅色錯誤提示卡,文字明講「以下數字不可信」——**絕對不能讓查詢失敗顯示成 $0**,這是專案的硬性原則(「缺就 loud」),PM/工程那邊已經因為這個原則抓過好幾次真實 bug
- **超收/超付**:金額顯示紅色 + 「超收/超付」前綴文字,不是只變色不加字
- **案場名稱過長**:排行區用 `truncate` + 固定寬度(`w-16`,64px)截斷,目前沒有 tooltip 顯示完整名稱——可能需要補
- **备注過長**:列表桌機表格版有 `max-w-[14rem]` + `truncate` + `title` tooltip;手機卡片版沒有截斷,會自然換行
- **超過 24 個月的歷史資料**:目前用實際測試資料驗證到 24 個月,更久的資料量還沒實測效能

## Animation / Motion

目前極簡,沒有進場動畫、沒有數字滾動效果:

| 元素 | 觸發 | 動畫 | Duration |
|---|---|---|---|
| `.nm-btn` / `.nm-btn-solid` | hover | border-color / color / background 漸變 | 150ms ease |
| 排行列 | hover | opacity 0.8 | Tailwind 預設 transition |
| 按鈕 | active(按下) | `transform: scale(0.98)` | 即時 |
| `prefers-reduced-motion: reduce` | 全域 | 背景動態紋理停用 | — |

**這塊完全開放給你設計**——沒有既定的轉場語言,可以考慮篩選切換時的內容淡入淡出、數字變化時的過渡效果等,只要遵守 `prefers-reduced-motion`。

## Accessibility Notes

- 篩選表單是原生 `<form method="get">`,無 JS 也能動作,鍵盤與螢幕閱讀器相容性天生較好
- 按鈕/連結目前**沒有系統性補 `aria-label`**,大部分依賴可見文字本身(如「編輯」「作廢」),但排行列跟比例條的可點區塊沒有額外的無障礙說明文字,只靠視覺
- 色彩語意(綠/紅/黃)全部**有文字或圖示輔助**(金額前綴、pill 文字),沒有單靠顏色傳達資訊的地方——這點要保持
- 目前沒有測試過鍵盤 tab 順序、focus 可視性在深色玻璃背景下的對比度,值得檢查(`.nm-focus:focus-visible` 有定義 outline,但實際對比度未驗證)
- 固定高度捲動面板(560px)裡的鍵盤 tab 導覽尚未測試是否會自動捲動到可視範圍內
