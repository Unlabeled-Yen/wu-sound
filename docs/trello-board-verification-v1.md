# 現場待辦看板驗證計畫 v1(2026-08-15)

對應 `trello-board-spec-v1.md`。這份回答一件事:**怎麼證明這套真的成立**,
而不是「開好了、看起來對」。

分三層,順序不能顛倒:

| 層 | 問什麼 | 什麼時候做 | 判定 |
|---|---|---|---|
| A 設定驗收 | 東西**開對了嗎** | 開版當天,10 分鐘 | 逐項 PASS / FAIL |
| B 機制行為驗證 | 自動化**真的會動嗎** | 開版當天,20 分鐘 | 逐項實測,有退路 |
| C 試跑驗收 | 人**真的會用嗎** | 開版後第 7 天 | 三個數字對及格線 |

**A 全過才做 B,B 全過或走完退路才開始 C。** 順序顛倒的話,第 7 天拿到難看的數字,
會分不清是人不用還是東西壞掉——那樣一週就白跑了。

## B. 機制行為驗證(開版當天)

**這一層是這份文件的重點。** 規格第 13 節列了 7 項「撰寫時沒有實機確認過」的
Trello 平台能力,這裡逐項實測,每項都給退路。

測試用一張拋棄式卡片 `[測試] 驗證用,測完刪掉` 跑完全部,測完刪掉。

### V-F01 — 建卡自動帶入成員

| | |
|---|---|
| 對應 | R-A01 / R-C02 |
| 做法 | 用員工帳號在「待辦」建一張卡,**不手動點成員** |
| 預期 | 卡片右下角出現該員工頭像 |
| **這項為什麼關鍵** | 這是「誰記誰做」在介面上唯一的體現。壞掉的話全部卡片無主,交接跟案子收尾都查不到人 |
| 退路 1 | Butler 取不到建卡者 → 改用 Trello 內建的「卡片建立者」資訊,老闆看得到,但卡面上不顯示 |
| 退路 2 | 都不行 → 卡片標題後綴加人名縮寫(`…—明`),醜但有效,且收回自建時仍解析得出來 |
| 結果 | ☐ PASS ☐ 走退路 1 ☐ 走退路 2 |

### V-F02 — 移入「卡住・等料」自動設到期日

| | |
|---|---|
| 對應 | R-A03 |
| 做法 | 把測試卡拖進「卡住・等料」 |
| 預期 | 卡片出現到期日 = 今天 +3 天 |
| 退路 | Butler 不支援相對日期 → 改成移入時通知該卡成員,人自己設。效果較弱但仍能讓卡片不靜靜躺著 |
| 結果 | ☐ PASS ☐ 走退路 |

### V-F03 — 完成欄自動封存

| | |
|---|---|
| 對應 | R-A04 |
| 做法 | **無法當天驗證**(要等 14 天)。當天改測「規則建得起來」:規則存檔不報錯 |
| 當天預期 | 規則出現在 Butler 規則清單,狀態啟用 |
| 第 14 天複驗 | 完成欄最舊的卡片消失,且在封存區找得到(**不是被刪掉**) |
| 退路 | 定時規則做不出來 → 改人工,老闆每月清一次完成欄。多一個人工動作,但這欄的維護是低頻低風險 |
| 結果 | 當天 ☐ / 第 14 天 ☐ |

**第 14 天那次複驗不要跳過。** 這條規則會刪東西,只驗「建得起來」不算驗過——
要親眼確認它封存而不是刪除。

### V-F04 — 看板 Email 地址

| | |
|---|---|
| 對應 | R-I02 |
| 做法 | 找到看板 Email 地址,從手機寄一封含照片的信過去 |
| 預期 | 「待辦」出現新卡,主旨變標題、照片變附件 |

| 退路 | 免費方案沒有此功能 → 語音管道改走 Trello API 建卡(要一支 token,工程量比寄信大但可行) |
| 結果 | ☐ PASS ☐ 走退路 |

### V-F07 — 通知真的收得到

| | |
|---|---|
| 對應 | R-A02 |
| 做法 | 用員工帳號丟一張卡到「要老闆決定」,**老闆的手機拿在手上看** |

## C. 試跑驗收(第 7 天)

開版後連續 7 天,第 7 天結算。**看數字,不看感覺。**

| 編號 | 指標 | 及格線 | 不及格代表什麼 |
|---|---|---|---|
| V-T01 | 一週建卡數 | ≥ 15 張 | 現場根本沒在用 → **輸入門檻問題**,優先做 R-I02、R-I03 |
| V-T02 | 建卡的人數 | ≥ 3 人 | 只有 1–2 人在丟 → **沒變成團隊習慣**,回去講開版清單第 9 步那兩句話 |
| V-T03 | 「要老闆決定」3 天內有回應的比例 | ≥ 80% | **制度問題不是軟體問題**(規格第 11 節) |
| V-T04 | Butler 額度警告 | 沒出現 | 出現的話要減規則,優先砍 R-A02 以外的 |

### 怎麼真的數出這些數字

免費方案沒有現成報表,**這四個數字要人工數,約 10 分鐘**。這裡寫清楚做法,
免得第 7 天才發現數不出來:

- **V-T01**:四欄卡片數相加,加上封存區當週的卡。開版那 10–15 張起始庫存**要扣掉**
  (那不是現場記的)。
- **V-T02**:掃一遍卡片右下角頭像,數不重複的人。V-F01 走退路 2 的話改看標題後綴。
- **V-T03**:「要老闆決定」與已移出該欄的卡片,逐張看第一則老闆留言的時間 −
  建卡時間 ≤ 3 天。**這就是為什麼待決事項第 3 題建議規定一律留言**——
  口頭回覆的話這個數字量不出來。
- **V-T04**:Butler 頁面若有額度提示會顯示在規則清單上方。

### 判定

- **三項都及格** → 續用。接著談要不要接語音管道、要不要收回自建。
- **只有 V-T03 不及格** → 不要改軟體。這是老闆的習慣問題,先解決人再說。
- **V-T01 或 V-T02 不及格** → 輸入門檻太高。優先補 R-I02、R-I03,再跑一週。
- **V-T01 不及格且 B 層走了 ≥ 2 條退路** → 平台能力可能撐不住這個設計,
  這時「收回自建」的優先度要往上調。

## D. 這份驗證計畫刻意不做的事

| 不做 | 理由 |
|---|---|
| 壓力測試、效能測試 | 4 欄、5 個人、一週十幾張卡,沒有效能問題可言 |
| 資安滲透測試 | Trello 的資安不由我們驗;我們能控的是**不上傳什麼**(R-G02),那是規則不是測試 |
| 每張卡的內容審查 | 抽查即可。要天天審就違反了「誰記誰做」的前提 |
| 使用者滿意度問卷 | 5 個人的團隊,直接問比發問卷準,而且 V-T01/T02 已經是行為數據——**人說喜歡但不用,以行為為準** |
