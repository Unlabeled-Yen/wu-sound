# Phase 1 規格 v1 — 員工手機三件套(2026-07-13)

範圍:**零用金報備(核心)+ 工作記錄(核心)+ 打卡(整合)**。
不在範圍:報價、庫存、內外帳模組(僅定義零用金的匯出格式與內帳銜接)。

## 現況證據(來自記帳樣本 2026.7)

- 員工代墊在內帳只有一行總額(「舒韶代墊 4983」「泯亘代墊 7457」),明細散在旁邊欄位的自由文字:「6/11 加油 500」「6/20停車 40」「6/25 變壓器 99」…
- 明細手動加總,樣本裡「總共4938」與帳上 4983 **不一致**——現行流程已在漏帳
- 帳內另有「不知道為什麼有多的 21014」孤行 + 兩處 `#REF!`
- 人員:老闆吳智仁;員工許舒韶、賴泯亘(+日後增員)
- 對帳節奏:每月發薪前一次結清

Phase 1 的核心價值主張:**讓「代墊明細 → 每人月結總額」這條線再也不會漏、不會對不上。**

## 角色與裝置

| 角色 | 裝置 | 能做 |
|---|---|---|
| 員工 | iPhone 手機瀏覽器(PWA,加到主畫面) | 打卡、報零用金、交工作記錄;只看得到自己的記錄 |
| 老闆 | 桌面瀏覽器為主(手機也可) | 看全部、確認零用金、月結對帳、匯出 |

登入:每人一組固定帳號(email magic link 或 PIN),3-6 人規模不做複雜權限。

## 功能一:零用金報備(核心)

### 員工端流程
1. 拍收據照片(或無收據時手填)
2. AI(Claude API)從照片抽取:日期、品項、金額 → **以草稿呈現,員工必須逐欄確認/修改後送出**
3. 選分類:油錢 / 停車過路 / 設備材料代墊 / 其他
4. 可綁定案場(選填,連動工作記錄的案場清單)
5. 送出後狀態 = `待老闆確認`

### 無靜默失效規則
- AI 讀不出金額 → 欄位留空 + 明顯提示「請手動填寫」,**絕不猜值**
- 照片上傳失敗 → 阻擋送出並顯示原因,不允許「沒照片但看起來成功」
- 金額加總一律由資料庫算(deterministic),AI 永遠不碰總額

### 老闆端流程
1. 儀表板:本月每人代墊累計(即時)、待確認清單
2. 逐筆看照片+明細,按「確認」或「退回(附原因,員工會看到)」
3. **月結畫面**:發薪前一鍵產出「每人本月已確認代墊總額 + 明細表」,格式對齊內帳習慣(日期 品項 金額),可複製貼進 Excel 或下載 CSV
4. 月結後該批記錄鎖定為 `已入帳`,不可再改(要改需退回重審,留 audit 記錄)

## 功能二:工作記錄(核心)

- 員工:選案場/案件 → 一句話描述 → 拍施工前/施工後照片(前後各至少可一張,可跳過但要明選「本次無照片」)
- 老闆:時間軸視圖(按日)+ 案場視圖(按案件聚合),取代現在在 LINE 逐一問
- 案場清單由老闆維護(簡單新增,一行一個)
- AI 副軌(選配,不擋主流程):把一句話自動正規化補上時間地點標籤,同樣草稿確認制

## 功能三:打卡(整合)

- 上班/下班兩鍵,記時間,**不記 GPS**(雇主明示)
- 補打卡:允許,但標記為「補登」並要求一句理由,老闆端可見——這是 loud 而不是擋人
- 老闆端:月視圖每人出勤表,可匯出
- 上線初期與 Google 表單並行兩週,核對無誤後才請雇主停用表單(不做無縫遷移賭注)

## 資料模型(Supabase / Postgres)

```
users        id, name, role(boss|staff), phone/email
sites        id, name, active
expenses     id, user_id, date, category, amount(int, 分為單位), item_text,
             site_id?, receipt_url?, ai_draft(json)?, status(draft|submitted|
             confirmed|rejected|booked), rejected_reason?, booked_batch_id?
worklogs     id, user_id, site_id, date, note, photos(json), no_photo_reason?
clockins     id, user_id, ts, type(in|out), is_backfill, backfill_reason?
book_batches id, month, created_at, totals(json)   -- 月結快照
audit_log    id, actor, action, target, ts, diff(json)
```

金額用整數(元);所有狀態轉移寫 audit_log。

## 技術與成本

- Next.js(App Router)+ Supabase(Auth/Postgres/Storage)+ Vercel,全部免費層
- Claude API:僅收據辨識與工作記錄正規化,估 <US$10/月
- 照片存 Supabase Storage(免費 1GB,收據照壓縮後綽綽有餘;滿了再談)
- PWA manifest,員工 iPhone「加入主畫面」

## 驗收條件

1. 員工用 iPhone 30 秒內完成一筆「拍照→確認→送出」零用金
2. AI 辨識錯誤時,畫面明確要求人工填寫,無任何預設猜值進入資料庫
3. 老闆月結畫面的每人總額 = 明細加總,由 DB 保證,並有一鍵匯出
4. 任何失敗(上傳、辨識、網路)都有可見錯誤訊息,無靜默吞掉
5. 打卡與 Google 表單並行期資料一致
6. 全流程不出現任何「AI」字眼——員工看到的只是「拍照自動帶入」
